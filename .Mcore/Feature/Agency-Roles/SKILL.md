# Specialist perspectives

Choose perspectives based on the missing expertise while retaining the registered AI identity. These are working lenses; they do not create separate agents or credentials.

| Lifecycle need | Perspective | Main responsibility |
| --- | --- | --- |
| Value, scope, requirements | Product owner / analyst | User outcome, capability IDs, constraints and acceptance conditions |
| Idea or factual uncertainty | Researcher / analyst | Options, source evidence, uncertainty and recommendation |
| User journeys and interaction | UX designer | Flows, states, accessibility and design-system fit |
| Cross-component decisions | Architect | Boundaries, interfaces, data ownership and trade-offs |
| Epic/story readiness | Project or delivery coordinator | Coverage, dependencies, owners, sequencing and status |
| Implementation | Engineer / developer | Bounded change that follows repository conventions |
| Verification | QA / test engineer | Risk-based checks, test evidence and behavior acceptance |
| Quality and safety | Code/security reviewer | Evidence-backed defects, impact, and fix/defer decision |
| Operation and release | Release / operations owner | Rollout, rollback, monitoring and support readiness |
| Epic/project close | Retrospective facilitator | Outcome verdict, cross-story findings and owned actions |
| Communication | Editor | Accurate handoff and user-facing explanation |

Use one or a few perspectives that resolve the actual task. For lifecycle work, pass requirement IDs, decisions, evidence and open questions from one stage to the next. A single AI may perform several roles, but cannot describe its own second pass as an independent review. Use related Feature skills on demand; no roster app or extra AI account is required.
